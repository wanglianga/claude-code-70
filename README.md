# 建筑工地食堂订餐留样与农民工补贴平台

面向建筑工地后勤的「订餐 → 备餐留样 → 刷脸/扫码取餐 → 补贴核算 → 异常多方协同 → 月底结算归档」一体化平台。
技术栈：**Vue 3 + Vite + Element Plus + ECharts（前端）**、**NestJS 10 + TypeORM + JWT（后端）**、**PostgreSQL 16（数据库）**、**Docker Compose 一键部署**。

---

## 一、原始需求

> 建设建筑工地食堂订餐留样与农民工补贴平台，可采用 Vue 3、NestJS 和 PostgreSQL。班组长每天提交用餐人数、工种、班次、夜宵需求、少数民族餐和临时加班后，平台根据实名考勤、宿舍人数、施工计划和食堂产能生成订餐。食堂备餐时记录菜单、食材批次、供应商、厨师、留样、温控和分餐时间；工人刷脸或扫码取餐后，平台核算个人餐补、企业补贴和自费金额。若工地临时停工、班组人数变动、食堂菜品不够、工人投诉变质、夜宵送到塔吊作业区或补贴金额争议，平台要把班组长、食堂、项目部、财务和安全员放在同一餐次里处理。月底结算时，订餐、取餐、补贴、报损、投诉、留样检测和供应商扣款进入工地后勤档案，用于控制浪费和保障食品安全。平台还要处理新工人未实名、工人跨班组取餐、食堂外包、项目部临时接待和夜间施工点分散等情况。对于高温天、雨天和封闭施工区域，送餐路线、保温和食品留样都要和安全管理结合起来。工地管理层还需要看到不同班组的实际取餐率、浪费率和投诉类型，便于调整菜单、补贴比例和食堂外包考核。

## 二、快速开始（Docker 一键部署）

> 验证方式 = **宿主机执行 `docker compose up -d`**，无需在本机安装 Node/Java/数据库等工具链。

```bash
# 1. 进入工程目录（内含 docker-compose.yml、.env）
cd /workspace

# 2. 可选：复制环境变量（已提供开箱即用的 .env）
#    cp .env.example .env

# 3. 构建并后台启动（db + backend + web 三个容器）
docker compose up -d --build

# 4. 查看健康状态（等待 backend health: healthy）
docker compose ps

# 5. 查看实际映射端口（不要假设固定端口）
docker compose port web 8080
```

启动成功后浏览器访问：

```
http://<宿主机IP>:<CC_PUBLISH_PORT>/
# 本机即 http://localhost:3070/   （CC_PUBLISH_PORT 默认 3070）
```

- 仅 **web（前端 nginx + 反代 /api）** 服务发布到宿主 `${CC_PUBLISH_PORT}:8080`；
- **PostgreSQL 不发布宿主端口**，backend 通过 compose 内网服务名 `db:5432` 访问；
- backend 也不发布宿主端口，仅由 web 容器反代。

停止与清理：

```bash
docker compose down          # 停止并删除容器（保留数据卷）
docker compose down -v       # 同时删除数据库数据卷（恢复全新演示数据）
```

健康检查：`GET http://localhost:3070/api/health` → `{"status":"ok","db":"up"}`。

## 四、功能与原始需求对照

| 需求点 | 实现位置 |
|---|---|
| 班组长提交人数/工种/班次/夜宵/少数民族餐/临时加班 | 订餐申报页（可编辑表格） |
| 依据实名考勤、宿舍人数、施工计划、食堂**产能**生成订餐 | `POST /api/meals/sessions/:id/generate`：基准上岗=max(考勤,计划,申报)再以宿舍人数封顶；+加班、夜宵 max(夜班基准,夜宵申报)+加班、清真份数保底；超产能用**最大余数法**硬约束分配（总量绝不超过产能、清真优先），逐班组分解写入 `demandDetail` 可追溯。**产能=0 表示停餐/零供给：各班组与总生成量均为 0、餐次置为 `stopped` 并拒绝取餐**（返回 `zeroSupply=true`） |
| 施工计划录入 | 订餐页「施工计划录入」（白班/夜班计划上岗人数、作业区）/ `POST /api/org/plans` |
| 调整宿舍人数 / 食堂产能 | 基础档案页「改宿舍人数 / 改产能」/ `PATCH /api/org/teams/:id`、`PATCH /api/org/canteens/:id` |
| 备餐：菜单/食材批次/供应商/厨师/留样/温控/分餐时间 | 备餐·留样·配送页 + `meal_preparations` |
| 食品留样（48h、≥125g、冷藏温控、检测结论） | 留样台账 + `food_samples`（自动算到期时间、合格/异常登记） |
| 刷脸/扫码取餐 + 个人餐补/企业补贴/自付核算 | 取餐终端 + `POST /api/meals/pickup` |
| 五方同一餐次协同（停工/人数变动/菜品不够/变质/塔吊夜宵/补贴争议） | 异常协同页时间线 + 联动（停工取消餐次、调整订餐、供应商扣款） |
| 月底结算入后勤档案 | 结算/后勤档案页 + `POST /api/stats/settle`（订餐/取餐/补贴/报损/投诉/留样/扣款） |
| 新工人未实名 | 取餐全额自付、标记未实名；实名登记（身份证+人脸）后享补贴，可走争议补发 |
| 跨班组取餐 | 取餐终端选取餐点班组，自动 `crossTeam` 标记 |
| 食堂外包 | 食堂档案含外包标识与考核分；供应商累计扣款进入考核与档案 |
| 项目部临时接待 | 基础档案页一键发起 `RECEPTION` 工单（食堂加备、财务单独核算，不占工人餐补） |
| 夜间施工点分散 | 夜宵送餐记录（区域/路线/份数/保温温度/配送员） |
| 高温/雨天/封闭区送餐与安全结合 | 送餐安全确认项（高空警戒、安全帽、封闭区登记、雨天防滑、夜间照明）+ `WEATHER` 工单 |
| **夜间加班临时加餐** | 「夜间加班加餐」页：班组长发起，平台检查**食堂值班/食材余量/配送点/餐补规则**；高风险作业区（塔吊/高空/封闭/深基坑等）须**安全员确认送餐路线与停留时间**；多施工点分别记录**签收人/温度/剩余/送达照片**，剩余触发漏领预警；刷脸/扫码领取，**夜间加餐企业全额承担（个人0元）**，费用与领取人员归入当夜宵餐次 |
| 班组取餐率/浪费率/投诉类型看板 | 管理看板（ECharts 柱状/饼图/餐费构成）+ 分班组明细表 |

## 五、推荐验证流程（一条完整业务链）

1. 用 `banzu1 / 123456` 登录 → 「订餐申报」修改人数/夜宵/少数民族餐 → 保存 → 点 **按考勤+产能生成订餐**；
2. 「备餐·留样·配送」登记菜单、食材批次、中心温度、分餐时间 → 对每样菜 **+留样（125g/48h）** → 登记塔吊区夜宵配送与安全确认；
3. 「取餐终端」选择工人**刷脸**或输入取餐码（如 `P1001`）**扫码** → 查看餐补/企补/自付；试选未实名工人（全额自付）、跨班组取餐点；
4. 「异常协同」打开「工人投诉凉拌黄瓜有异味」→ 查看五方时间线 → 财务执行**供应商扣款**、填写结论**结案**；
5. 「工人实名考勤」对未实名工人做实名登记、切换考勤、跨班组调动；
6. 用 `admin` 登录「管理看板」查看各班组取餐率/浪费率/投诉类型；「结算/后勤档案」选择月份 **生成结算档案**。

## 六、工程结构

```
.
├── docker-compose.yml          # db + backend + web（仅 web 发布宿主端口）
├── .env / .env.example         # CC_PUBLISH_PORT、数据库、JWT 配置
├── backend/                    # NestJS + TypeORM
│   ├── Dockerfile              # 多阶段构建，非 root(node)，自带 HEALTHCHECK
│   └── src/
│       ├── entities/           # 16 个实体（用户/班组/工人/考勤/施工计划/食堂/供应商/
│       │                       #   餐次/订餐(含需求分解)/备餐/留样/配送/取餐/异常/动作/月档案）
│       ├── auth/               # JWT + 角色守卫
│       ├── modules/            # org / meal / incident / stats 业务模块
│       └── seed/               # 启动演示数据
└── frontend/                   # Vue3 + Vite + Element Plus + ECharts
    ├── Dockerfile              # 多阶段构建，nginx 非 root 监听 8080 + HEALTHCHECK
    ├── nginx.conf              # 静态资源 + /api 反代 backend:8080
    └── src/views/              # 登录/布局/看板/订餐/备餐留样/取餐/异常/结算/工人/基础档案
```

## 七、主要 API

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/auth/login` | 登录获取 JWT |
| GET | `/api/meals/sessions?date=` | 餐次列表（含汇总） |
| POST | `/api/meals/orders` | 班组长订餐申报 |
| POST | `/api/meals/sessions/:id/generate` | 四来源合成需求 + 最大余数法产能分配（返回逐班组可追溯 breakdown） |
| GET/POST | `/api/org/plans` | 施工计划（白班/夜班计划上岗人数） |
| PATCH | `/api/org/teams/:id` `/api/org/canteens/:id` | 调整宿舍人数 / 食堂产能 |
| POST | `/api/meals/preparations` `/samples` `/deliveries` | 备餐/留样/配送 |
| POST | `/api/meals/pickup` | 刷脸/扫码取餐并核算费用 |
| POST | `/api/extra-meals/precheck` `/extra-meals` | 加餐四项检查 / 班组长发起加餐 |
| POST | `/api/extra-meals/:id/safety` `/canteen-confirm` | 安全员确认高风险路线停留 / 食堂备餐扣余量 |
| POST | `/api/extra-meals/points/:pid/depart` `/receive`、`/extra-meals/pickup` | 多点出发/签收（签收人/温度/剩余/照片）/领取归餐次 |
| GET/POST | `/api/incidents`、`/:id/actions`、`/:id/resolve` | 异常五方协同 |
| GET | `/api/stats/dashboard`、POST `/api/stats/settle` | 看板与月底结算 |
